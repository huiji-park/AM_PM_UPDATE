# AM_PM MVP — 제약사항 검토

- 작성일: 2026-10-03 (Asia/Seoul)
- 검토 대상: 상세 설계 0.1, API 계약, 화면·검증 명세, 구조도, 예시 화면 시안
- 반영 버전: 상세 설계·API·화면 명세 0.2, 사용자 검토 전
- 목적: 학습·포트폴리오 MVP의 현실적인 경계와 테스트해야 할 실패 조건 정의
- 관련 문서: [설계](2026-10-03-am-pm-mvp-design.md), [테스트 계획](../plans/2026-10-03-am-pm-mvp-test-plan.md)

## 1. 판단 요약

Vue + FastAPI + PostgreSQL 단일 서버 구성은 현재 범위에 맞는다. 새 분산 시스템이나 새 제품 기능을 도입할 이유는 확인하지 못했다. 다만 다음 여섯 항목은 구현자에 따라 다른 동작이 나올 수 있어 문서 0.2에서 보완했다.

1. 개발 Swagger도 프론트와 동일 출처를 사용하도록 경로 지정.
2. 설명의 허용 길이와 충돌하는 본문 바이트 상한 보완.
3. 인증 Session과 업무 Session의 수명을 명확히 구분.
4. Nginx 요청 제한의 평균 rate·burst·지연 여부·429 설정 명시.
5. 보드의 여러 요청에 대한 일관성 보장 범위 축소·정확화.
6. DB 연결 고갈 시 대기 제한과 오류 응답 정의.

이 문서의 ‘반영’은 설계 문구에 반영했다는 뜻이다. 기능 구현이나 테스트 통과를 뜻하지 않는다. 공개 실사용 서비스에 필요한 계정 복구·이메일 소유 확인은 여전히 첫 버전 밖이다.

## 2. 검토 기준과 우선순위

| 우선순위 | 기준 | 처리 |

## 4. 구체적 근거와 보완

### C-01: 개발 API 문서의 출처

원 설계는 PUBLIC_ORIGIN을 `http://localhost:5173`으로 고정하고 POST/PATCH/DELETE의 Origin 누락·불일치를 거부한다. API 서버의 `http://localhost:8000/docs`에서 실행한 요청은 브라우저 Origin이 달라 거부될 수 있다. Origin 헤더는 프론트 JavaScript에서 임의로 위조하도록 설계하지 않는다.

보완: FastAPI의 docs_url을 `/api/docs`, openapi_url을 `/api/openapi.json`, redoc_url을 null로 정한다. 개발 사용자는 5173 출처의 문서만 열고 같은 경로 프록시를 통과한다. production에서는 docs_url과 openapi_url을 null로 한다. FastAPI는 이 문서 URL을 설정하거나 비활성화할 수 있다. [공식 문서](https://fastapi.tiangolo.com/tutorial/metadata/)

### C-02: 문자 수와 바이트 수

실제 작은 Python 계산으로 다음 값을 확인했다. 제품 서버 테스트는 아니다.

| 입력 | JSON 직렬화 | 바이트 수 | 64KiB | 256KiB |
|---|---|---:|---|---|
| 제목 이모지 200개 + 설명 이모지 10,000개 | UTF-8 직접 출력 | 40,829 | 통과 | 통과 |
| 같은 값 | ASCII 유니코드 escape 출력 | 122,429 | 거부 | 통과 |

동일한 의미의 유효 입력을 인코딩 방식만으로 거부하지 않도록 기본 상한을 262144바이트로 바꿨다. 상한을 넘는 임의 공백·추가 바이트까지 허용하겠다는 의미는 아니다. 최대 길이보다 긴 필드는 422이고, 원문 전체가 상한을 넘으면 413이다. 요청 압축은 지원하지 않는다.

### C-03: Session 수명

업무 서비스의 begin 이전에 같은 Session으로 인증 SELECT를 실행하면 이미 트랜잭션이 시작되어 begin 충돌을 만들 수 있다. 문서 0.2는 인증 조회를 짧게 종료하고 사용자 ID만 넘긴 뒤 업무 Session에서 begin하도록 명확히 했다. 응답 생성 중 ORM lazy loading으로 닫힌 Session을 다시 사용하지 않는지도 검사한다.

### C-04: 요청 제한

Nginx rate 제한은 leaky bucket이며 burst를 지정해도 기본적으로 지연이 발생할 수 있다. `nodelay`를 지정해야 지연 없이 허용 또는 거부하고, 기본 거부 상태는 503이므로 429를 명시해야 계약에 맞는다. [Nginx 공식 문서](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html)

가입·로그인은 하나의 zone을 공유한다. 외부 X-Forwarded-For 문자열을 바꾸어 제한을 우회해서는 안 된다. 기본 배포 앞에 추가 로드밸런서를 놓는다면 신뢰할 프록시 CIDR과 실제 IP 복원 정책은 별도 설계가 필요하다. 공유 Wi-Fi의 여러 사용자가 같은 제한을 받는 것은 알려진 제약이다.

### C-05·C-09: 읽기 일관성

PostgreSQL의 READ COMMITTED는 같은 트랜잭션이어도 SELECT마다 다른 snapshot을 볼 수 있다. count와 items를 서로 다른 SELECT로 가져오려면 처음부터 읽기 전용 REPEATABLE READ를 쓰거나 단일 SELECT로 합쳐야 한다. [PostgreSQL 공식 문서](https://www.postgresql.org/docs/current/transaction-iso.html)

그 보장도 HTTP 요청 하나의 경계다. TODO 열을 읽은 후 업무가 IN_PROGRESS로 바뀌고 두 번째 열을 읽으면 같은 업무를 두 번 받을 수 있다. 반대 순서에서는 두 응답 모두에 업무가 없을 수 있다. 이 때문에 ‘항상 누락 없음’을 보장하지 않는다.

프론트는 중복 ID에 가장 큰 version을 택한다. 계속 쓰기가 발생하는 동안 완전한 snapshot을 보장하지 않는다. 쓰기가 멈춘 뒤 전체를 다시 조회하면 중복·누락 없이 같은 상태에 도달해야 한다. 프로젝트 전체 집계와 현재 필터의 카드 수는 원래 의미부터 다르므로 같다고 표시하지 않는다.

### C-06: 계정과 팀원 추가의 한계

이메일 인증과 복구가 없으므로 입력된 이메일 주소의 실제 소유자를 보장할 수 없다. 최초 가입자가 그 문자열을 차지할 수 있고, 비밀번호를 잃으면 복구할 수 없다. 또한 이메일로 즉시 추가하므로 대상자의 사전 수락이 없다.

현재 사용자가 선택한 목적에 맞춰 테스트·시연 계정만 사용하는 MVP에서는 이 경계를 명시하고 유지한다. 공개 실사용을 시작하는 결정을 내리면 이메일 검증·복구·초대 수락을 후속 요구사항으로 승격한다. 이번 검토가 그런 기능 추가를 자동 승인한 것은 아니다.

### C-07·C-15: 규모와 성능

제품 상한이 없다고 무한한 데이터를 처리하는 성능을 보장하지 않는다. 지원 검증 기준은 프로젝트당 업무 1,000개, 동시 사용자 10명이다. 하나의 프로젝트를 동시에 변경하는 요청은 프로젝트 행 잠금 때문에 대기한다. 세션 인증도 DB 조회를 필요로 한다.

pool_size=5, max_overflow=5, pool_timeout=3초를 기준으로 풀 고갈 시 503 RESOURCE_BUSY로 끝내고 연결이 회수되는지 검사한다. 대량 담당 해제·삭제가 statement timeout을 만나면 전체가 rollback되어야 한다. 별도 프로젝트의 쓰기까지 같은 행 잠금으로 묶어서는 안 된다.

페이지 100개 업무 각각에 최대 길이 설명을 포함하면 응답 크기가 커진다. 현재 범위에서 즉시 API를 바꾸지 않고 일반 입력·최대 입력을 나눠 측정한다. 실제 측정이 목표를 충족하지 못하면 요약 DTO·검색 인덱스·잠금 범위 변경을 근거와 함께 제안한다.

### C-12: 시안과 제품의 차이

현재 시안은 예시 데이터와 로컬 동작으로 화면을 검토하기 위한 것이다. 실제 계정·권한·DB 테스트의 대체물이 아니다. 시안의 일부 동작은 성공 후 화면을 예시로 보여줄 뿐 실제 저장을 하지 않는다. 시안은 좁은 화면에서 보드 열을 세로로 쌓으며, 제품 명세는 보드 영역 가로 스크롤을 기본으로 한다.

제품 수용 검증은 구현된 Vue·FastAPI·PostgreSQL을 모두 연결한 환경에서 수행한다. 지난 시안의 클릭 검증 결과를 API·보안·영속성 테스트 통과로 옮겨 적지 않는다.

### C-13: 현재 환경 확인

2026-10-03 현재 이 채팅의 PowerShell PATH 기준으로 확인한 값이다.

| 항목 | 관찰 | 영향 |
|---|---|---|
| node / npm | PATH에서 확인, Node v20.9.0 | 채택할 Vite·테스트 도구와 호환 확인 필요 |
| python / py / uv | PATH에서 발견하지 못함 | 프로젝트 Python 3.13과 실행 환경 준비 필요 |
| docker / psql | PATH에서 발견하지 못함 | DB·프록시 통합 테스트 실행 경로 필요 |
| Codex 번들 Python | 절대 경로로 실행 가능 | 문서 계산에 사용, 프로젝트 런타임 준비와 구분 |
| 신규 backend / frontend | 아직 없음 | 제품 테스트 명령·설정도 아직 없음 |

PATH에서 찾지 못했다는 사실로 기기에 설치되어 있지 않다고 단정하지 않는다. psql CLI 자체는 필수가 아니지만 접속 가능한 독립 PostgreSQL 테스트 DB는 필요하다. DB 제공은 Docker Compose 또는 별도 로컬/CI DB를 선택할 수 있으며 이번 작업에서는 설치·연결 설정을 변경하지 않았다.

## 5. 유지하는 범위 제한

- 같은 출처의 브라우저 앱을 기준으로 한다. 별도 모바일 앱·서드파티 API 인증은 포함하지 않는다.
- 프로젝트 소유자 한 명과 팀원만 있다. 전역 관리자·조직 권한은 없다.
- 일정은 Asia/Seoul 기준의 날짜다. 사용자별 시간대·시간 예약은 없다.
- 채팅·실시간 보드 동기화·간트·알림·파일 업로드는 다음 단계다.
- 삭제는 영구적이며 휴지통·자동 복원은 없다. 백업/복구는 수동 시연 운영 절차다.
- 기존 데이터 이관을 하지 않는다. 원본 계정·세션·업로드 파일을 새 서비스에 복사하지 않는다.
- 재시도에 따른 생성 중복을 완전히 방지하는 idempotency API는 없다.

## 6. 사용자 검토 시 결정할 사항

| 결정 | 권장 기본값 | 다른 선택의 영향 |
|---|---|---|
| 첫 공개 범위 | 통제된 포트폴리오 시연 | 실사용 공개 시 이메일 검증·계정 복구·초대 수락 재설계 |
| 모바일 보드 | 현재 제품 명세의 가로 스크롤 + 목록 전환 유지 | 세로 열 방식 선택 시 화면 명세·반응형 수용 기준 수정 |
| API 재전송 | 현재처럼 자동 쓰기 재시도 없음 | 자동 재시도를 원하면 idempotency 설계 추가 |

문서 모순을 해소하는 0.2 보완은 작성했으며, 위 제품 정책은 검토 기본값으로 남긴다. 질문에 대한 답이 없다고 다른 범위를 승인한 것으로 취급하지 않는다. 문서 작성·검토에는 추가 답변이 필요하지 않으므로 테스트 계획까지 완성한다.

## 7. 이번 검토의 증거

수행: 관련 설계 파일 대조, 시안의 범위 확인, CLI 탐지, Node 버전 확인, JSON 바이트 크기 계산, Nginx·FastAPI·PostgreSQL 공식 문서 확인.

미수행: 신규 제품 실행, DB 마이그레이션, pytest·Vitest·Playwright 제품 테스트, 침투 테스트, 부하 테스트, 실제 배포. 해당 결과는 [테스트 계획](../plans/2026-10-03-am-pm-mvp-test-plan.md)의 실행 기록으로 추후 증명해야 한다.
